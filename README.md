# LINE OA External Chat POC

โปรเจกต์ทดสอบแนวคิด: ลูกค้าทัก LINE OA → ข้อความเข้าระบบภายนอก (หน้า UI นี้) → agent พิมพ์ตอบในหน้า UI → ข้อความถูกส่งกลับไปที่ลูกค้าทาง LINE จริง

โครงสร้าง: FastAPI (`app.py`) เก็บข้อความใน Postgres (ฟรีถาวรผ่าน Neon — ดูขั้นตอนที่ 0) และเสิร์ฟหน้า UI ง่ายๆ ที่ `static/index.html` รองรับข้อความตัวอักษร รูปภาพ และไฟล์แนบทั้งสองทาง

## ระบบบัญชี + login จริง

ทุกคนที่เข้าเว็บนี้ต้อง login ด้วยบัญชีจริงก่อน (username/password เก็บแบบเข้ารหัส bcrypt ในฐานข้อมูล) ไม่มีการ "สลับตัวตนได้เอง" แบบเดิมอีกแล้ว — ทุกข้อความที่ตอบลูกค้า ทุกโน้ตภายใน และการมอบหมายแชท จะผูกกับบัญชีที่ login อยู่จริงโดยอัตโนมัติ ทำให้รู้ชัดว่าใครตอบแชทไหนไปบ้าง

- **บัญชีแรก (bootstrap)**: ระบบสร้างบัญชี admin ให้อัตโนมัติตอนรันครั้งแรก (username/password มาจาก env var `ADMIN_BOOTSTRAP_USERNAME`/`ADMIN_BOOTSTRAP_PASSWORD` ถ้าไม่ตั้งจะใช้ค่า default `admin` / `changeme123`) **ต้อง login แล้วเปลี่ยนรหัสผ่านทันที** (ปุ่ม 🔑 มุมบนซ้าย)
- **จัดการบัญชี**: บัญชีที่มีสิทธิ์ `admin` จะเห็นปุ่ม 👥 มุมบนซ้าย เปิดหน้า `/admin` เพิ่มบัญชีเซลใหม่ (username, รหัสผ่าน, ชื่อที่แสดง, สีป้าย, สิทธิ์ `admin`/`sales`) ปิด/เปิดใช้งานบัญชี หรือรีเซ็ตรหัสผ่านให้คนอื่นได้ บัญชีที่ปิดใช้งานจะถูกตัดสิทธิ์ทันที (ล็อกอินซ้ำไม่ได้ และ session ที่เปิดอยู่ก็ใช้ต่อไม่ได้)
- **ใครตอบแชทไหน (ฝั่ง admin)**: ทุกข้อความที่ตอบลูกค้า (ทั้งพิมพ์และแนบไฟล์) จะโชว์ชื่อบัญชีที่ส่งไว้เหนือข้อความนั้นในหน้าแชท
- **ใครตอบแชทไหน (ฝั่งลูกค้าเห็นด้วย!)**: กดปุ่ม 📷 มุมบนซ้าย อัปโหลดรูปโปรไฟล์ของตัวเอง — จากนั้นทุกข้อความที่บัญชีนั้นตอบไป (พิมพ์ตอบ/ข้อความสำเร็จรูป/ส่งรูป/ส่งไฟล์/ส่งลิงก์ลงทะเบียน) จะแสดง**ชื่อ+รูปของบัญชีนั้นในฟองข้อความที่ลูกค้าเห็นจริง** (ใช้ฟีเจอร์ [Customize icon and display name](https://developers.line.biz/en/docs/messaging-api/icon-nickname-switch/) ของ LINE) โดยจะมีคำว่า `from 'ชื่อ OA'` ต่อท้ายอัตโนมัติกันสับสน เช่น `คุณเอ - ผู้เชี่ยวชาญโครงการ A from นกเอี้ยง`
  - ข้อจำกัด: เปลี่ยนได้แค่**ฟองข้อความ** — ชื่อ/รูปที่หัวห้องแชท, หน้าโปรไฟล์ธุรกิจ, ลิสต์แชท และลิสต์เพื่อนของลูกค้า ยังคงเป็นโปรไฟล์ OA เดิมเสมอ (ข้อจำกัดของ LINE เอง แก้ไม่ได้)
  - ถ้าบัญชีไหนยังไม่อัปโหลดรูป ข้อความจะแสดงเป็นโปรไฟล์ OA ปกติ (ไม่มีชื่อกำกับ) จนกว่าจะอัปโหลดรูป
- **มอบหมายแชท**: dropdown ในหน้าคุยดึงรายชื่อจากบัญชีจริงที่ยัง active อยู่ (ไม่ใช่ mock อีกต่อไป)
- **โน้ตภายใน**: แท็บ "โน้ตภายใน" บันทึกได้หลายรายการต่อแชท ผู้เขียนดึงจากบัญชีที่ login อยู่อัตโนมัติ (แก้ไขปลอมชื่อไม่ได้แล้ว) แนบไฟล์ได้ ลูกค้าไม่เห็นข้อมูลส่วนนี้เด็ดขาด
- **ข้อความสำเร็จรูป**: ปุ่มเหนือช่องพิมพ์ 5 อัน กดแล้วแทรกข้อความลงช่องพิมพ์ให้แก้ก่อนส่งได้ (ไม่ auto-send) แก้ข้อความตัวอย่างได้ที่ตัวแปร `QUICK_REPLIES` ใน `static/index.html`
- **ค้นหาแชท**: ช่องค้นหาเหนือลิสต์แชท กรองตามชื่อลูกค้า (client-side)
- **ข้อมูลลูกค้า (เก็บอีเมล/เบอร์โทร)**: แท็บ "ข้อมูลลูกค้า" ในหน้าคุย กดปุ่ม "ส่งลิงก์ขอข้อมูลเพิ่มเติม" ระบบจะส่งลิงก์ฟอร์ม (เปิดในแอป LINE ผ่าน LIFF) ให้ลูกค้ากรอก ชื่อ-นามสกุล อีเมล เบอร์โทร วันเกิด เอง เมื่อลูกค้ากดส่งฟอร์ม ข้อมูลจะผูกกับแชทนั้นอัตโนมัติและโชว์อยู่ในแท็บนี้ทันที (ต้องตั้งค่า LIFF ก่อนใช้งาน — ดูขั้นตอนที่ 4)

## ขั้นตอนที่ 0: สร้างฐานข้อมูล Postgres ฟรีถาวร (Neon)

เดิม POC นี้เก็บข้อความใน SQLite ไฟล์เดียว ซึ่งบน Render free tier disk เป็น ephemeral — ข้อมูลหายได้เมื่อ instance restart/redeploy (นี่คือสาเหตุที่แชทหายไปตอนที่ทิ้งไว้ข้ามคืน) แก้โดยย้ายไปเก็บใน Postgres ที่ Neon ซึ่งมี free tier แบบไม่มีวันหมดอายุ

1. เข้า https://neon.tech → กด **Sign Up** → สมัครด้วย GitHub (บัญชีเดียวกับที่ใช้ push โค้ด จะง่ายสุด)
2. หลัง login จะมีตัวช่วยสร้างโปรเจกต์ → ตั้งชื่อโปรเจกต์ (เช่น `line-oa-poc`) → เลือก region ใกล้ๆ (Singapore ถ้ามี) → **Create Project**
3. หน้าถัดไปจะโชว์ **Connection string** ให้คัดลอกไว้ หน้าตาประมาณ:
   ```
   postgresql://<user>:<password>@<host>/<dbname>?sslmode=require
   ```
   (ถ้าหาไม่เจอ ไปที่ Dashboard โปรเจกต์ → แท็บ **Connection Details** → คัดลอกค่าใน dropdown "Connection string")
4. เก็บค่านี้ไว้ — จะใช้เป็นค่า `DATABASE_URL` ทั้งตอนรัน local และตอนตั้งค่าบน Render

## ขั้นตอนที่ 1: สร้าง LINE Messaging API Channel

1. เข้า https://developers.line.biz/console/ แล้ว login ด้วยบัญชี LINE
2. สร้าง **Provider** ใหม่ (ถ้ายังไม่มี) — ใส่ชื่อบริษัท/โปรเจกต์
3. ในหน้า Provider กด **Create a new channel** → เลือก **Messaging API**
4. กรอกข้อมูลช่อง (ชื่อบอท, ไอคอน, หมวดหมู่) แล้วสร้าง
5. เข้าไปที่ channel ที่สร้าง → แท็บ **Messaging API**:
   - เลื่อนลงไปที่ **Channel access token** กด **Issue** เพื่อออก token แบบ long-lived → คัดลอกเก็บไว้
   - แท็บ **Basic settings** → คัดลอก **Channel secret**
6. ในหน้า Messaging API เดียวกัน **สแกน QR code** ด้วย LINE บนมือถือ เพื่อเพิ่มบอทเป็นเพื่อน (ใช้ทดสอบ)
7. ปิดฟีเจอร์ auto-reply ที่ชนกับ POC: เข้า https://manager.line.biz เลือกบัญชีนี้ → **Settings > Response settings** → ปิด **Greeting messages** และ **Auto-reply messages**, เปิด **Webhooks**

## ขั้นตอนที่ 2: รันในเครื่องตัวเอง (ทดสอบก่อน deploy)

```bash
cd line_oa_poc
python3 -m venv venv && source venv/bin/activate   # หรือข้ามถ้าไม่อยากใช้ venv
pip install -r requirements.txt

cp .env.example .env
# แก้ .env ใส่ LINE_CHANNEL_ACCESS_TOKEN, LINE_CHANNEL_SECRET (ขั้นตอนที่ 1)
# และ DATABASE_URL (connection string จาก Neon ในขั้นตอนที่ 0)
# LIFF_ID ข้ามไปก่อนได้ (เว้นว่างไว้) จนกว่าจะ deploy เสร็จแล้วค่อยตั้งค่าตามขั้นตอนที่ 4
# SECRET_KEY ใส่สตริงสุ่มยาวๆ อะไรก็ได้ (ใช้เข้ารหัส session login)
# ADMIN_BOOTSTRAP_USERNAME / ADMIN_BOOTSTRAP_PASSWORD ใช้ตอนสร้างบัญชี admin แรกเท่านั้น (ดูขั้นตอนที่ 5)

uvicorn app:app --reload --port 8000
```

เปิด http://localhost:8000 จะพาไปหน้า **/login** ก่อน (ยังไม่มีข้อความจากลูกค้า เพราะ LINE ยังยิง webhook มาที่ localhost ไม่ได้)

ถ้าต้องการทดสอบในเครื่องจริงกับ LINE ต้องเปิด public URL ชั่วคราวด้วย `ngrok http 8000` แล้วเอา URL ที่ได้ (เช่น `https://xxxx.ngrok-free.app/webhook`) ไปใส่ใน Messaging API tab > **Webhook URL** แล้วกด **Verify**

## ขั้นตอนที่ 3: Deploy ขึ้นออนไลน์ฟรี (Render.com)

Render มี free web service tier ไม่ต้องใส่บัตรเครดิต (มีข้อจำกัด: sleep เมื่อไม่มีคนใช้ ~15 นาที ตื่นมาช้าประมาณ 30-50 วิ — ยอมรับได้สำหรับ POC/demo)

1. Push โฟลเดอร์ `line_oa_poc` นี้ขึ้น GitHub repo (public หรือ private ก็ได้)
2. ไปที่ https://render.com → สมัคร/login (ผูกกับ GitHub ได้เลย)
3. กด **New +** → **Web Service** → เลือก repo ที่ push ไว้
4. Render จะอ่าน `render.yaml` ในโปรเจกต์อัตโนมัติ (Build command / Start command ตั้งไว้ให้แล้ว) หรือถ้าไม่ auto-detect ให้กรอกเอง:
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `uvicorn app:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips='*'`

   (ส่วน `--proxy-headers --forwarded-allow-ips='*'` สำคัญมาก — ถ้าไม่ใส่ ฟีเจอร์ส่งรูป/ไฟล์จะสร้างลิงก์ผิด เพราะเซิร์ฟเวอร์จะไม่รู้ว่าตัวเองถูกเรียกผ่าน https)
5. เลือก plan **Free**
6. ใส่ Environment Variables (กด **Add from .env** แล้วเลือกไฟล์ `.env` ในเครื่องจะง่ายสุด เพราะมีครบทั้ง 3 ค่า):
   - `LINE_CHANNEL_ACCESS_TOKEN` = token จากขั้นตอนที่ 1
   - `LINE_CHANNEL_SECRET` = secret จากขั้นตอนที่ 1
   - `DATABASE_URL` = connection string จากขั้นตอนที่ 0
   - `LIFF_ID` = เว้นว่างไว้ก่อนได้ (ใส่ค่าอะไรก็ได้ชั่วคราว เช่นเว้นว่าง) แล้วค่อยกลับมาใส่จริงตามขั้นตอนที่ 4 หลัง deploy สำเร็จ
   - `SECRET_KEY` = **สำคัญ ต้องตั้งค่าจริง อย่าเว้นว่าง** สุ่มสตริงยาวๆ มาใส่ (รันคำสั่งนี้ในเครื่องเพื่อสร้างค่าสุ่ม: `python3 -c "import secrets; print(secrets.token_hex(32))"`) ถ้าไม่ตั้งค่านี้ไว้ ทุกคนจะถูกเด้งออกจากระบบ (ต้อง login ใหม่) ทุกครั้งที่ Render restart เซิร์ฟเวอร์ (ซึ่งฟรีเทียร์จะ sleep แล้ว restart บ่อยเวลาไม่มีคนใช้)
   - `ADMIN_BOOTSTRAP_USERNAME` / `ADMIN_BOOTSTRAP_PASSWORD` = ตั้งไว้เผื่ออยาก custom บัญชี admin แรก ไม่ตั้งก็ได้ (จะได้ `admin` / `changeme123` เป็นค่า default — ดูขั้นตอนที่ 5)
7. กด **Create Web Service** (หรือถ้า service มีอยู่แล้ว ไปที่ **Environment** tab เพิ่ม `DATABASE_URL` แล้วไปที่ **Settings** แก้ Start Command ตามด้านบน แล้วกด **Manual Deploy > Deploy latest commit**) รอ build เสร็จ จะได้ URL แบบ `https://line-oa-poc-xxxx.onrender.com`
8. กลับไปที่ LINE Developers Console → Messaging API tab → **Webhook URL** ใส่ `https://line-oa-poc-xxxx.onrender.com/webhook` → กด **Verify** → เปิด toggle **Use webhook**
9. เปิด `https://line-oa-poc-xxxx.onrender.com` ในเบราว์เซอร์ — นี่คือหน้า UI ที่ส่งให้คนอื่นทดสอบได้เลย (ยังไม่มี login/สิทธิ์ ใครมีลิงก์เห็นแชททั้งหมด — พอสำหรับ POC แต่ไม่ควรใช้ข้อมูลลูกค้าจริง)

ทดสอบ: ทักบอทผ่าน LINE จากมือถือ → ข้อความจะโผล่ในหน้า UI ภายในไม่กี่วินาที → พิมพ์ตอบในหน้า UI → ข้อความไปเด้งที่ LINE จริงของลูกค้า

## ขั้นตอนที่ 4: ตั้งค่า LIFF เพื่อเก็บอีเมล/เบอร์โทรลูกค้า

ฟีเจอร์ "ข้อมูลลูกค้า" ใช้ LIFF (LINE Front-end Framework) เปิดหน้าฟอร์มในแอป LINE โดยไม่ต้องให้ลูกค้า login เอง ต้องทำหลังจาก deploy ขึ้น Render แล้วเท่านั้น (เพราะต้องใช้ URL จริงของเว็บ ไม่ใช่ localhost)

1. เข้า https://developers.line.biz/console/ → เลือก Provider/Channel เดียวกับที่ใช้ตอน ขั้นตอนที่ 1 (channel ประเภท Messaging API)
2. ไปที่แท็บ **LIFF** ในหน้า channel → กด **Add**
3. กรอกข้อมูล:
   - **LIFF app name**: ตั้งชื่ออะไรก็ได้ เช่น `ฟอร์มข้อมูลลูกค้า`
   - **Size**: เลือก **Full**
   - **Endpoint URL**: ใส่ `https://line-oa-poc-xxxx.onrender.com/register` (URL จริงจากขั้นตอนที่ 3 ต่อท้ายด้วย `/register`)
   - **Scope**: ติ๊ก `profile` (ใช้ดึง LINE user_id ของคนกรอกฟอร์ม)
   - ปิด **Bot link feature** ไว้ก็ได้ (ไม่จำเป็นสำหรับฟอร์มนี้)
4. กด **Add** จะได้ **LIFF ID** หน้าตาประมาณ `1234567890-AbCdEfGh` คัดลอกไว้
5. ไปที่ Render → service ของเรา → แท็บ **Environment** → แก้ค่า `LIFF_ID` เป็นค่าที่คัดลอกมา → กด **Save** (Render จะ redeploy ให้อัตโนมัติ)
6. ทดสอบ: เปิดหน้าเว็บ → เลือกแชทลูกค้า → แท็บ "ข้อมูลลูกค้า" → กด "ส่งลิงก์ขอข้อมูลเพิ่มเติม" → เช็คที่ LINE ของลูกค้า (หรือมือถือตัวเอง) ว่าได้รับข้อความลิงก์ → กดลิงก์ ฟอร์มควรเปิดในแอป LINE เอง (ไม่ใช่ browser ข้างนอก) → กรอกแล้วกดส่ง → กลับมาเช็คแท็บ "ข้อมูลลูกค้า" ในหน้าเว็บ ควรเห็นข้อมูลที่กรอกไปแล้ว

**ข้อควรระวัง**: ลิงก์ฟอร์ม (`https://liff.line.me/<LIFF_ID>`) ต้องเปิดจากในแอป LINE เท่านั้นถึงจะดึง user_id ได้ถูกต้อง ถ้าเปิดจาก browser ทั่วไปจะเปิดไม่ได้/ไม่ทำงานตามที่ตั้งใจ — ระบบส่งลิงก์นี้ผ่านข้อความ LINE ให้ลูกค้าอยู่แล้วจึงกดจากในแอปโดยอัตโนมัติ

## ขั้นตอนที่ 5: Login ครั้งแรก + สร้างบัญชีทีมเซล

1. เปิดเว็บ `https://line-oa-poc-xxxx.onrender.com` จะเด้งไปหน้า **/login**
2. Login ด้วยบัญชีที่ระบบสร้างให้อัตโนมัติ:

## Rich Menu: ให้ลูกค้ากดกรอกข้อมูลเองได้ทุกเมื่อ

นอกจากปุ่ม "ส่งลิงก์ขอข้อมูลเพิ่มเติม" ที่เซลกดส่งให้ลูกค้าเป็นรายคน ยังตั้ง Rich Menu (เมนูรูปภาพด้านล่างจอแชท) ให้ลูกค้ากดกรอกฟอร์มเองได้เลยทุกเมื่อ ไม่ต้องรอเซล

**รันครั้งแรก (ต้องมี `LIFF_ID` ใน `.env` แล้ว — ดูขั้นตอนที่ 4):**

```bash
cd line_oa_poc
python3 scripts/setup_rich_menu.py
```

สคริปต์นี้จะ: ลบ Rich Menu เก่า (ถ้ามี) → สร้างใหม่จากรูป `richmenu/contact_form.png` → ตั้งเป็นเมนูเริ่มต้นให้ลูกค้าทุกคนทันที ลูกค้าที่แชทอยู่จะเห็นเมนูใหม่โผล่ขึ้นทันทีโดยไม่ต้องทำอะไรเพิ่ม

**ถ้าอยากเปลี่ยนรูป/ข้อความในเมนู**: แก้/แทนที่ไฟล์ `richmenu/contact_form.png` (ขนาดต้องเป็น 2500x843 พิกเซล) แล้วรันสคริปต์ซ้ำได้เลย — สคริปต์จะลบของเก่าแล้วสร้างใหม่ให้เองไม่ต้องเข้า Console

**ถ้าอยากได้หลายปุ่มในเมนูเดียว** (เช่น กรอกข้อมูล + ดูโปรโมชั่น + ติดต่อเซล): ต้องแก้ตัวแปร `areas` ในสคริปต์ให้มีหลาย object แต่ละอันมี `bounds` (ตำแหน่ง/ขนาดของปุ่มนั้นบนรูป) และ `action` ของตัวเอง — บอกได้ถ้าต้องการให้ทำเพิ่ม

## เรื่องรูปภาพ/ไฟล์

- **รับจากลูกค้า**: รูปภาพ วิดีโอ ไฟล์ (PDF, Word ฯลฯ) ที่ลูกค้าส่งเข้ามา ระบบจะดาวน์โหลดเก็บไว้ในฐานข้อมูลและแสดงในหน้า UI ได้หมด
- **ส่งจากเรา (agent)**: กดปุ่ม 📎 เพื่อแนบไฟล์ตอนตอบ
  - ถ้าเป็นรูปภาพ → ส่งเป็น image message ปกติ ลูกค้าเห็นรูปในแชท
  - ถ้าเป็นไฟล์อื่น (PDF, Word, ฯลฯ) → LINE Messaging API **ไม่มี message type สำหรับส่งไฟล์แนบโดยตรง** (รองรับแค่ text/รูป/วิดีโอ/เสียง/sticker/template) ระบบเลยส่งเป็นข้อความตัวอักษรที่มีลิงก์ให้ลูกค้ากดดาวน์โหลดแทน
- สติกเกอร์และตำแหน่งที่ตั้ง (location) จากลูกค้า ตอนนี้ยังไม่แสดงผล จะขึ้นเป็นข้อความแจ้งว่า "ยังไม่รองรับ" แทน

## ข้อจำกัดของ POC นี้ (ไม่เหมาะกับ production)

- Session login เก็บเป็น cookie ที่เข้ารหัสด้วย `SECRET_KEY` ฝั่งเดียว ไม่มี "จำอุปกรณ์"/2FA/ล็อกอินพร้อมกันหลายที่แบบมีการแจ้งเตือน — ถ้าต้องการความปลอดภัยระดับ production ควรทำเพิ่ม
- ไม่มีการจำกัด rate การ login (brute-force รหัสผ่านได้ในทางทฤษฎี) — ควรเพิ่ม rate limiting ถ้าจะเปิดให้คนนอกเข้าถึงเว็บได้
- ตอบกลับผ่าน Push API ล้วน (ไม่ใช้ reply token) มีโควต้าข้อความฟรีต่อเดือนจำกัด ใช้เกินมีค่าใช้จ่าย เช็คโควต้าได้ที่ LINE OA Manager
- ไม่มี retry/queue เมื่อ LINE API ล้มเหลว
- รูปภาพ/ไฟล์เก็บเป็น binary ในฐานข้อมูลตรงๆ (ง่ายสุดสำหรับ POC) ถ้าจะใช้จริงจังควรย้ายไป object storage (เช่น S3, Cloudinary) แทน
- Neon free tier มี storage limit 0.5GB และจะ auto-pause ฐานข้อมูลถ้าไม่มีการเชื่อมต่อนานเกินไป (ตื่นเองอัตโนมัติเมื่อมี request ใหม่ ช้าไม่กี่วินาที ไม่ต้องทำอะไรเพิ่ม)
- ฟอร์มเก็บข้อมูลลูกค้า (LIFF) มี checkbox ยินยอมให้เก็บข้อมูลตาม PDPA แล้ว แต่เป็นแค่ข้อความยินยอมพื้นฐาน ถ้าจะใช้เก็บข้อมูลลูกค้าจริงควรให้ทีมกฎหมาย/ผู้เชี่ยวชาญ PDPA ตรวจข้อความและกระบวนการอีกครั้ง
